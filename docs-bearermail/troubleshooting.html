Troubleshooting

The failures that have actually happened, and the smallest thing that fixes each one.

Mail isn't arriving

  1. Check Account health first. Open Settings → Account health (or go to /settings?section=health). If a sign-in, calendar or push has broken, it says which and gives the one-click fix.
  2. Is port 25 reachable? From outside your network: telnet mail.yourdomain.com 25 should show the Postfix banner. If it hangs, your ISP or host is blocking inbound port 25 — you can't receive directly.
  3. Is the MX right? dig MX yourdomain.com should point at your mail hostname, and that A record must be DNS-only (grey cloud), not proxied.
  4. Watch the conversation: docker compose logs -f mta shows every SMTP session live.

Log lines worth knowing:

  • NOQUEUE: reject: RCPT ... Relay access denied — the recipient isn't in MAIL_ACCOUNTS.
  • status=bounced with a DNS error — the container can't resolve; check the host's DNS.

Mail goes to spam / gets rejected

  • Check the triad: SPF, DKIM and DMARC all published and valid? Use the admin DNS checker or an external validator (e.g. mail-tester.com).
  • PTR record: no reverse DNS on your IP is the most common reason Gmail distrusts a new server.
  • Home IP? Stop delivering directly and relay through Mailjet — Sending: direct or relayed.
  • New domain? Fresh domains have no reputation. Warm up with real correspondence before any volume.

A container is restart-looping

The app containers run database migrations on every boot. A failing migration restart-loops the container:

docker compose logs php | tail -40   # or worker / scheduler / imap-supervisor

Look for the migration error at the top of the loop. Common cause: a non-idempotent migration replayed against a partially-migrated database. Fix the migration to be idempotent (CREATE TABLE IF NOT EXISTS, guarded ALTERs), then rebuild all four app services — they share one image:

docker compose --profile mail up -d --build
Rebuild everything, not one service

All app services share the plmail-fork:latest image. Rebuilding only php leaves the others on the old image with the old bug.

Relay stopped working

  • Check Admin → Mail server: is the relay still configured, or did someone clear the host field (which reverts to direct delivery)?
  • Remember: MAIL_RELAY* env vars override the UI. If you set them in the shell and forgot, the UI can't change them.
  • Mailjet secret rotated? Update it in the same place you set it.

Android app won't pair / sync

  • Auth proxy in front? The app needs a direct path to the server — bypass forward-auth (Authentik etc.) for the mail hostname.
  • "Scan the code" closes the app or says the camera could not be started: update to 0.0.33 or later (the scanner uses ZXing instead of ML Kit). Meanwhile use Enter the address instead. Check that Android's Camera access quick-settings toggle is on.
  • No update offered: the app checks at most once an hour. Use Drawer → Check for updates, or fully close and reopen the app.
  • Signed out after reinstalling: expected. Updates keep the login; uninstalling or Clear storage removes it. Pair again.
  • App closed unexpectedly: reopen it, tap Copy on the crash report and include it in a GitHub issue.
  • Release workflow fails with No key with alias … found in keystore: the KEY_ALIAS secret must contain only the alias word (check with keytool -list), then re-run the Release workflow.
  • Updates failing to install: every APK must be signed with the same key. If you installed a debug build or a differently-signed APK, uninstall first — Android won't let a mismatched signature update in place.

Share links don't work

  • Check the link hasn't expired — expiries are enforced server-side.
  • If the share page loads but download fails, check the php container's logs and that the app_drive volume (/app/var/drive) is writable and has disk space.
  • "Drive is switched off": an admin turned Drive off for the owner (Admin → Drive or Admin → Users), which also stops their links.
  • Report emails not arriving: they are sent from an administrator's own mailbox, so at least one admin needs a working mail account. The report still shows in Admin → Drive either way.

A mail app suddenly can't log in

  • Its address was probably blocked after too many wrong passwords. Open Admin → Security → Mail login blocking, find the address under Blocked now, and click Unblock (or Unblock and always allow). Then fix the password in that app, or it will be blocked again.
  • The badge says Waiting for mail server: restart the mail containers once (./update.sh does it) so the mail server starts asking.
  • The web app and the BearerMail phone app are never blocked — they don't sign in on port 993.

A code or plan card is wrong

  • Cards are made when mail arrives, by the version you were running then. After an update, re-read recent mail: 
    docker compose exec php php bin/console app:backfill insights --since=2026-10-01
    The re-read replaces that mail's old code and plan cards.
  • A plan card on something that isn't a plan: click Not an event.
  • A new card doesn't appear on a page that was already open: refresh the page (a hard refresh, Ctrl+F5, if it still doesn't).

Single sign-on doesn't work

  • Nothing in the logs, sign-in just fails: a bot shield (Anubis, Cloudflare challenge) in front of the provider is answering the server's requests with an HTML challenge. Test and fix as on Single sign-on → Behind Anubis.
  • "…did not tell BearerMail your email address": the provider user has no email, or the email scope isn't selected on the provider.
  • "…has not confirmed your email address": authentik 2025.10+ sends email_verified: false by default — add the verified email mapping.
  • The button lands straight in your mail: that's success; the provider already had you signed in.
  • Locked out with the password form hidden: go to /login?password=1.
  • After any change at the provider: docker compose exec php php bin/console cache:pool:clear cache.app.

A new user can't send or receive (AUTHENTICATIONFAILED)

Their mail account points at a mailbox that was never created on the mail server — people added before the admin area could create mailboxes. Run:

docker compose exec php php bin/console app:mail:mailbox from-accounts --dry-run   # see who is missing one
docker compose exec php php bin/console app:mail:mailbox from-accounts

Each missing mailbox is created with the password already saved in that person's mail account. For new people, fill in Mailbox on Admin → Users → New user.

A shared note won't open after the password

Update the server (./update.sh): on older builds the right password looked like it did nothing. A wrong password shows "That password is not right"; after ten wrong tries in fifteen minutes the link waits a while.

Voice notes won't record

  • The browser asks for the microphone the first time; if it was refused, allow it for your BearerMail site in the browser's site settings (the padlock in the address bar) and reload.
  • Recording needs the site on https://.
  • On the phone: Android Settings → Apps → BearerMail → Permissions → Microphone.

Note reminders don't arrive

  • No email: the reminder is mailed from and to your first mail account, so you need one that can send.
  • No notification: notifications need push set up on the server (Admin → Push) and allowed on the device. On Android, check the Reminders channel isn't switched off.
  • A reminder more than an hour overdue (the server was off) is skipped.

Admin → Updates says "development" or never sees a new version

  • Run ./update.sh once with a current version: it now stamps the build with the commit it was made from. Builds made before that show "development".
  • Set Follow to Main — update.sh installs the latest main. Releases only changes when a version is tagged.
  • Check now asks GitHub's registry immediately; otherwise it checks every hour.

The phone's icon didn't change

The launcher icon follows Settings → Appearance → Logo on the web, and changes when the app next syncs with the server. Open the app once; some launchers take a minute to redraw. You need an app version with the BearerMail icons (install the latest release).

Still stuck

Collect docker compose logs --tail=100 <service> for the failing service and open an issue on the relevant repo — server or android. Say what you expected, what happened, and what the logs show.
