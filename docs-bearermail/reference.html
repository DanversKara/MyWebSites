Config reference

Every BearerMail-specific environment variable, port, and volume. For upstream plMail's own variables, see the upstream configuration reference.

Environment variables (mail server)

VariableDefaultWhat it does
MAIL_DOMAINexample.comYour mail domain. Used for the Postfix hostname, DKIM selector domain, and default aliases.
MAIL_HELO(empty → mail.$MAIL_DOMAIN)Hostname Postfix announces. Override if your PTR record uses a different name.
MAIL_ACCOUNTS(empty)localpart:password pairs, comma-separated. The mailbox list — this is user management.
MAIL_RELAYHOST(empty = direct)Outbound relay, e.g. [in-v3.mailjet.com]:587. Settable from Admin → Mail server instead.
MAIL_RELAY_USER(empty)Relay login (e.g. Mailjet API key).
MAIL_RELAY_PASS(empty)Relay secret (e.g. Mailjet secret key). Never paste into chat or tickets.
MAIL_CERTS_PATH(empty = self-signed)Host path containing fullchain.pem + privkey.pem for Dovecot's port 993.
CF_API_TOKEN(empty = DDNS off)Cloudflare API token (DNS:Edit) for the dynamic-DNS updater.
CF_ZONE(empty)DNS zone for the updater, e.g. yourdomain.com.
CF_RECORDmailHostname the updater keeps pointed at your IP.
MAIL_LOGIN_GUARDonFailed-login blocking for IMAP (port 993). off disables it; settings live in Admin → Security.

Environment variables (app)

VariableDefaultWhat it does
DRIVE_QUOTA_MB5120Drive storage per person when Admin → Drive has no setting (0 = no limit).
OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET(empty = off)Single sign-on from the environment. Only used when Admin → SSO holds no complete provider; what's saved there wins. See Single sign-on.
OIDC_BUTTON_LABEL, OIDC_SCOPES, OIDC_AUTO_CREATE, OIDC_REQUIRE_VERIFIED_EMAILsee upstreamThe rest of the environment single sign-on settings, as in the upstream OIDC page.

When both are set, the MAIL_RELAY* env vars win over the Admin → Mail server relay settings. To manage the relay purely from the UI, leave the env vars empty.

Ports

PortServiceExposed toNotes
25mta (Postfix)InternetInbound mail. Must be reachable for receiving.
587mta (Postfix)Compose network onlyDeliberately not published — plMail submits here internally.
143mailstore (Dovecot)Compose network onlyplMail reads mail here, like any IMAP account.
993mailstore (Dovecot)Internet (TLS)Direct IMAP for Thunderbird/phone apps. Self-signed cert unless MAIL_CERTS_PATH is set.

Volumes & files

Volume / pathWhat lives there
mail_dataMaildir mailboxes. Back this up.
mail_dkimDKIM private key. Back this up — losing it means rotating DNS.
app_drive → /app/var/driveDrive files, plus _settings.json with the Admin → Drive limits, and _notes/ with notes' pictures, drawings and voice notes. Included in app:backup.
mail_config → /etc/plmail-mail-configShared between the app and the mail containers: relay settings, aliases, SMTP keys, login_guard.json (mail login blocking settings) and auth_policy_key (the secret the mail server uses to ask the app about logins; made on first start).

Applying changes

# Update to the latest version (backup, download, rebuild):
./update.sh

# Mailboxes on the built-in server (see Mail server → Managing mailboxes):
docker compose exec php php bin/console app:mail:mailbox list
docker compose exec php php bin/console app:mail:mailbox from-accounts

# Send note reminders that are due now (runs on its own every minute):
docker compose exec php php bin/console app:notes:reminders

# Re-read old mail for plan and code cards after an update:
docker compose exec php php bin/console app:backfill insights --since=2026-10-01

# After editing MAIL_ACCOUNTS or relay env vars:
docker compose --profile mail up -d --force-recreate mta mailstore

# After editing anything else:
docker compose --profile mail up -d --build

Migrations run automatically on container boot — you don't run them by hand. If a container is restart-looping on a migration error, check docker compose logs <service> before anything else.
