Zoiper on a mobile phone (away)

Account → domain sip.example.com, transport TLS, outbound proxy sip.example.com:5061. Under Advanced → Encryption choose SRTP (SDES), not ZRTP. Android and iOS can close a background app's connection — allow Zoiper to run in the background (or use push), or incoming calls go to voicemail.

Desk phones

Set Proxy, Registrar and Outbound proxy to the PBX IP, port 5060, transport UDP, and turn SRTP off on the LAN. If you use "dial 9 for an outside line", update the phone's dial plan (e.g. 9xxxxxxxxxx).

Or skip the softphone: the Android app

Instead of (or as well as) Zoiper, users can use the My Phone app. It sets up its own phone login with one tap and signs in on the extension's separate app line (<username>-app), so it rings together with the desk phone or Zoiper without replacing them.

Check it

The phone appears under Dashboard → Signed in now as Online, showing whether it's internal or external.

Controlling access

The Features page in the admin panel controls every star code: turn each one on/off for the whole system, set the default access (By plan, All users, Admins only, or No one), and override per user with Allow/Deny. One exception: *88 (push-to-talk) is not a Features-page code — it is controlled per account by the Allow push-to-talk flag on the login, plus the user's own switch in their Settings. For example, give *555 (ChanSpy) to a supervisor without making them a full admin, or disable *70 (DISA) entirely. The rule follows the person, so it's the same from a desk phone, Zoiper or the Android app.

By plan is the default for every code except *555 (admins only). A new account starts with no star codes; a user gets a code when their active plan includes it (Billing → plan → Star codes included), and it goes off again if the plan lapses or changes. Without a plan they get the Star codes (no plan) set under Billing → User access — empty by default; tick *97/*98 there if you don't sell plans and want everyone to reach their voicemail. Admins can always use every code, and a per-user Allow/Deny always wins. Each user's row on the code's page shows Now: whether they can use it and why (e.g. “in plan Pro”, “no plan”, “Allow override”). Users who existed before this change kept the codes they had (an Allow override each); set them to Default to hand them to their plan.
